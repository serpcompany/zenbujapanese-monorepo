- **Browser extension, A.** Before merge, the code that needs no browser is tested, both builds
  and both packages must pass, and the browser tests load the test build in Chromium: the pages,
  the offscreen document's return, the content script on a real page, and a fixture release's
  install, offline. The `verify-extension` skill shows the same in branded Chrome with proof. Main gap,
  both tracked in [`tech-debt.md`](tech-debt.md) (Browser extension): the test surface's menu and
  dialog are driven by hand (#1062), and branded Chrome, where Chrome's own Translator runs, runs
  only on an agent's Mac, not in CI (#1063). The header's site switch on a real tab, Settings, and a translation in Translate are checked by hand, with no browser test (the browser tests drive only the side panel's tab bar, the last tab, Back from Image Search, the account, and a transcript word's card on the page and, from the keyboard, in the panel), and so is the side panel's width at 320 and 380 px (#1112, two rows in [`tech-debt.md`](tech-debt.md): one for the pages, one for the width). The YouTube content script runs in the browser tests on the
  agent Chrome harness's stand-in watch page under YouTube's host, but never on YouTube. The browser tests install a
  fixture release but don't look a word up in it, resume a cut download, fail a wrong SHA-256,
  or update to a second release; the welcome tab has no screenshots, the install-to-first-lookup
  time is unmeasured on a throttled Chrome, and the conformance suites don't run on WebAssembly
  (#1071, four rows in [`tech-debt.md`](tech-debt.md): the install, the screenshots, the time, and the `instr` scans with the suites).
- **Account, B.** Every behavior in its product doc has a test before merge, and the browser tests
  sign in, out, and delete, sign in from the website, and sync two profiles, against the account
  service from the checkout. Main gap: Google and Apple are only stand-ins, and release builds
  draw no Continue with Google until the extension's Google client exists (#987), and nothing has
  signed in or synced against staging, from the website (#1130) included; a sync wait lost when
  Chrome stops the service worker waits for the next change, start, or panel open.
- **Word Detail, B.** Every behavior in its product doc has an interaction test before merge, on
  the fixtures, and the word popup's expanded card draws them. The browser tests expand a page's
  popup into a word's full entry, scroll it inside the card, and follow its Open on
  zenbujapanese.com to a new tab, and measure テーブル's and 食べる's headword at 380 px. Main gap:
  the kanji and form pages run only in happy-dom, a check by hand covers only the expanded card,
  and the whole dictionary waits for #1071.
- **Page lookup and word popup, B.** Each behavior in their product docs has a browser test on a
  light and a dark local page before merge, with unit and DOM tests beside the code. Main gap,
  in [`tech-debt.md`](tech-debt.md): only the local page, Playwright's Chromium, and the fixture
  release's few words, text with an emoji segments unlinked (#1093), and a long page's first scan slows as it draws.
