# Quality: the iOS app

A grade for each area of the app. [`quality.md`](quality.md) has the scale, columns, and re-grading.

The app's tests are the `SearchExperienceTests` and `TranslatorCoreTests` targets, in
`apps/ios/Modules/Tests/`, and the UI tests, `ZenbuJapaneseUITests`, in `apps/ios/UITests/`, each
run with `xcodebuild` on iPhone and iPad Simulators and the Mac ([`ios.md`](agents/ios.md), Tests on
every platform). Each behavior in the product docs names its check. The `iOS` workflow runs them on
a macOS runner only once the owners turn it on (`IOS_SWIFT_TESTS`), so until then they run only by
hand. The product docs are in [`apps/ios/docs/product/`](../apps/ios/docs/product/index.md), and the
manual checks named below are in `ios.md`.

- **Search, C.** Thorough tests, three suites the website is held to, and UI tests of the screen on
  iPhone, iPad, and the Mac (the Grade panel's only on iPhone), but no CI for them. What the app
  finds, ranks, sorts, filters, and lists is the shared core's, whose own tests do run before merge.
  Main gap: nothing runs the app's tests before merge, so neither the Swift that hands the core its
  rows and decodes its answers nor the screens are checked then; no suite records sentence search
  (#470); and that iOS hands a website link to the app is checked only on a device.
- **Word and kanji detail, C.** The recorded suites cover what the word, kanji, and element pages
  draw, each page's model is the shared core's, and UI tests drive the menu, lists, notes, kanji,
  and stroke order on every device. Main gap: no CI for the app's own tests.
- **Player, C.** The caption model and Recent's sync are tested, and UI tests drive the screen and a
  search's results page with YouTube stood in. Main gap: no CI, and YouTube's real player, caption
  fetch, and live results page are checked only by hand.
- **Lists and Known Words, C.** Storage is well tested, and UI tests drive the screens' swipes,
  right-clicks, and the list picker. Main gap: no CI, and Edit's reordering is untested.
- **Translate, C.** The engine and History are tested with fakes, and UI tests walk every screen on
  a scripted conversation, held step by step where a state passes quickly, on all three devices, so
  what's left by hand is how the screens look, Auto-Lock, and what needs a microphone. The on-device
  recognizers were checked on an iPhone with a scripted conversation (#627), and `translate-replay`
  runs the app's recognizer and engine on recordings from it, on a Mac. Main gap: no CI runs the
  app's tests; and the recorded-audio check is local only, on three recordings of synthesized
  voices, since CI has no speech models to run it (#640).
- **Account and sync, C.** The client, the profile's sync, and Apple's and Google's sign-in with
  only their sheets stood in, are tested against a stub server, and UI tests drive the sign-in sheet
  and a signed-in Profile. Main gap: no CI, and a real Apple or Google sign-in only on a device.
- **Account tab and Profile, C.** The profile's rules, Reading Aids' preferences, an unreadable
  profile or Media Library index, and when a deleted photo's image goes are tested, and UI tests
  drive every row, the profile, and saving and deleting a Media Library photo. Main gap: no CI.
- **iPad and Mac, C.** The adapters, the command routing, and the project's platform settings are
  tested, every package test and UI test runs on the iPhone and iPad Simulators and the Mac, the
  layouts are checked at the iPad's orientations and the Mac's smallest window, and a check keeps
  iPhone-only APIs out of feature code. Main gap: the CI job that runs them is off, so a change that
  breaks one platform merges unnoticed until someone runs the tests, and the Mac's UI tests need
  Automation Mode turned on once per Mac. On hold since 2026-10-18: tests added since, such as
  `GradeInputUITests`, have run only on iPhone. Nothing compares screenshots: a screen that works
  but is drawn wrong, as the Mac's forms and row icons were, is found only by looking at it.
- **Image Search, C.** Recognition runs on real images, and UI tests open an image from a stand-in
  camera, and pasted on the Mac, through the real import and recognition. The flash kept for the
  camera is tested as a rule; the camera itself only runs on a device. Main gap: Apple Translation
  doesn't run in the Simulator, and the on-device model runs only where the Simulator's runtime
  matches the Mac, so translation and Context are checked by hand, on a device.
- **Shortcuts and Siri, C.** Each link is tested to its screen on every device. Main gap: no CI.
